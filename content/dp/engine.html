Before you code

The 60-second pattern recognition engine

Use the constraints and the shape of the state space before reaching for a template. This is the fastest way to avoid forcing the wrong DP pattern.

Two players alternate turns?→ Pattern 17 · Game Theory / Minimax
Count numbers in a huge range with digit constraints?→ Pattern 14 · Digit DP
N is around 20 and used/visited items matter?→ Pattern 11 · Bitmask DP
Optimal contiguous subarray?→ Pattern 2 · Kadane / Subarray DP
Two strings, alignment or transformation?→ Pattern 5 · LCS / Two-String DP
Palindrome or interval [i,j]?→ Pattern 7 · Palindromic Interval DP
Grid / matrix with restricted movement?→ Pattern 9 · Grid DP
Longest increasing / chaining?→ Pattern 6 · LIS
Buy/sell, paint houses, explicit modes?→ Pattern 10 · State Machine DP
Tree, DAG or topological dependency?→ Pattern 12 / 13
Partition / split / merge an interval?→ Pattern 8 · MCM / Partition DP
Pick/skip with capacity?→ Pattern 3 if single-use · Pattern 4 if reusable
Linear recurrence or i depends on i−1/i−2?→ Pattern 1 · Fibonacci / Linear DP
Probability or expected value?→ Pattern 15 · Probability DP
Counting structures like BSTs / parentheses?→ Pattern 16 · Catalan / Counting DP
Transition needs fast range max/min/query?→ Pattern 18 · DP + Data Structures
