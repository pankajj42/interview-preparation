P01
Pattern 1

Fibonacci & Linear DP

Guide addition

Think of this as the “small memory” pattern. If the future only needs a few previous answers, keep exactly those states and avoid carrying the whole history.

Recognition signal

  • The answer at position i depends only on a constant number of previous positions (i-1, i-2, etc.).
  • The state space is 1-dimensional.
  • Often disguised as "ways to climb", "ways to decode", "house robber".
Recognition promptAsk: “What is the smallest suffix of the past that determines the next answer?”

State & transition

  • State: dp[i] = answer for first i elements / i-th step.
  • Transition: dp[i] = f(dp[i-1], dp[i-2], ..., dp[i-k])
  • Base: dp[0], dp[1] given by problem.

Common Pitfalls

  • Off-by-one in base cases.
  • Integer overflow on large n (use modulo).
  • Circular arrays (Pattern 1 + two passes).

P02
Pattern 2

Kadane's & Subarray DP

Guide addition

Kadane’s key trick is to anchor the state at the current endpoint. You are not solving every interval; you are deciding whether the current element joins the best suffix or starts a new one.

Recognition signal

  • Find the contiguous subarray (slice) that maximizes/minimizes a metric.
  • The optimal subarray ending at i either extends the one ending at i-1 or starts fresh at i.
Recognition promptAsk: “If the best segment must end here, is it better to extend or restart?”

State & transition

  • State: dp[i] = best subarray sum ending at index i.
  • Transition: dp[i] = max(nums[i], nums[i] + dp[i-1])
  • Answer: max(dp[i]) over all i.

Variations

  • Product: Track both max_ending and min_ending (sign flips).
  • Circular: Max of (Kadane's, Total Sum - Min Subarray Sum).
  • Two subarrays: Prefix + suffix Kadane's.

P03
Pattern 3

0/1 Knapsack & Subset Sum

Guide addition

This is the canonical one-time choice pattern. The difficult part is usually identifying the capacity/state and remembering that the same item must not leak into the current iteration.

Recognition signal

  • A set of items. Each item can be chosen at most once.
  • A capacity constraint (weight, sum, count of zeros/ones).
  • The decision for item i is binary: TAKE or SKIP.
Recognition promptAsk: “If I process item i now, can it be used again?” If no, think backwards over capacity.

State & transition

  • State: dp[i][w] = max value using first i items with capacity w.
  • Transition:
  • Space Optimization: 1D array, iterate w backwards.

Variations

  • Count ways: Use + instead of max.
  • 2D capacity: Nested knapsack (e.g., Ones and Zeroes).
  • Target Sum: Transform to subset sum problem.

P04
Pattern 4

Unbounded Knapsack

Guide addition

The same capacity idea becomes different when reuse is legal. Forward iteration lets the current item contribute again, which is the heart of unbounded knapsack.

Recognition signal

  • Items can be chosen unlimited times.
  • Classic: "Coin Change", "Rod Cutting", "Perfect Squares".
  • The order of iteration matters: loop capacity forward.
Recognition promptAsk: “Does choosing this item leave me in a state where I may choose it again?”

State & transition

  • State: dp[w] = min/max value for capacity w.
  • Transition: dp[w] = min/max(dp[w], dp[w - weight[i]] + value[i])
  • Iteration: Outer loop over items, inner loop w from weight[i] to capacity.

P05
Pattern 5

LCS & Two-String DP

Guide addition

Two-string DP is usually a coordinate system over two prefixes. Most transitions mean “consume both”, “skip from the first”, or “skip from the second”.

Recognition signal

  • Two sequences/strings. Alignment, transformation, matching, or editing.
  • The answer for prefixes s1[0..i] and s2[0..j] builds from smaller prefixes.
Recognition promptAsk: “What happens if I reveal one more character from each prefix?”

State & transition

  • State: dp[i][j] = answer for s1[0..i-1] and s2[0..j-1].
  • Core Transition:
  • Space: Can optimize to O(min(n,m)).

P06
Pattern 6

LIS & Monotonic Sequences

Guide addition

LIS is a subsequence pattern, so gaps are allowed. The O(n log n) version does not store the actual best sequence; it stores the best possible tail for each length.

Recognition signal

  • Find the longest subsequence where elements are strictly increasing (or non-decreasing).
  • Can be solved in O(n^2) with pure DP or O(n log n) with patience sorting + binary search.
  • Often appears as "chain", "envelopes", "stacking".
Recognition promptAsk: “Can I append this value to a sequence I already built?”

State & transition

  • DP approach: dp[i] = 1 + max(dp[j]) for all j < i where nums[j] < nums[i].
  • Patience sorting: Maintain tails[] array. tails[k] = smallest tail of all increasing subsequences of length k+1.

P07
Pattern 7

Palindromic Interval DP

Guide addition

Interval DP turns a string into a family of nested subproblems. The boundaries i and j are the state; many transitions either remove an endpoint or choose how an interval is resolved.

Recognition signal

  • Problems about substrings (contiguous) rather than subsequences.
  • State is defined by interval boundaries [i, j].
  • Expanding from center or shrinking from ends.
Recognition promptAsk: “If I know the answer inside [i+1, j-1], what can I conclude about [i, j]?”

State & transition

  • State: dp[i][j] = answer for substring s[i..j].
  • Transition: If s[i] == s[j], result depends on dp[i+1][j-1].
  • Iteration: i from n-1 down to 0, j from i to n-1.

P08
Pattern 8

MCM & Partition DP

Guide addition

Partition DP is “choose the last split”. It is powerful whenever a contiguous region can be divided into two independently solved regions plus a merge/partition cost.

Recognition signal

  • Break an array/string into contiguous partitions optimally.
  • Try every split point k between i and j.
  • Cost of partition depends on left and right subproblems.
Recognition promptAsk: “Where could the final split have been?”

State & transition

  • State: dp[i][j] = optimal cost for subarray [i, j].
  • Transition:
  • Optimization: Knuth optimization, Divide & Conquer DP when quadrangle inequality holds.

P09
Pattern 9

2D/3D Grid DP

Guide addition

Grid DP is graph DP on a structured graph. The coordinates are the state, and the movement rules tell you exactly which predecessor states are legal.

Recognition signal

  • Movement on a matrix/grid with restricted directions (usually right + down).
  • Can extend to 3D with two simultaneous paths (Cherry Pickup).
Recognition promptAsk: “From which neighboring cells can I legally arrive here?”

State & transition

  • State: dp[r][c] = optimal value reaching cell (r, c).
  • Transition: dp[r][c] = grid[r][c] + min/max(dp[r-1][c], dp[r][c-1])
  • 3D variant: dp[r1][c1][r2][c2] or dp[step][r1][r2] for two walkers.

State Machine DP

Guide addition

State-machine DP makes hidden conditions explicit: holding vs not holding, cooldown vs active, attendance counts, colors, etc. Once the state is correct, transitions become mechanical.

  • Often appears as stock problems, paint house problems, or robot states.
Recognition promptAsk: “What information about the past changes which moves are legal next?”

P11
Pattern 11

Bitmask DP

Guide addition

Bitmask DP compresses a subset of up to roughly 20–22 items into one integer. It is the pattern to reach for when the state is fundamentally “which things have already been used?”

Recognition signal

  • N <= 20 (sometimes 22). You need to track which elements have been visited/used.
  • The subset of used items is represented as an integer bitmask.
  • Classic: TSP, assignment problems, covering sets.
Recognition promptAsk: “Can the entire set of used/visited items fit into a bitmask?”

State & transition

  • State: dp[mask][i] = optimal value for subset mask ending at item i.
  • Transition: dp[mask | (1<<j)][j] = min(dp[mask][i] + cost[i][j])
  • Iteration: mask from 0 to (1<<n) - 1.

P12
Pattern 12

DP on Trees

Guide addition

Tree DP exploits the absence of cycles. A node can combine already-solved child states in a post-order traversal, often with include/exclude or a small local state.

Recognition signal

  • The problem is defined on a tree structure.
  • Optimal substructure is computed via post-order DFS from children to parent.
  • Sometimes requires a second pre-order pass (re-rooting) to compute answers for all nodes as roots.
Recognition promptAsk: “If I cut the edge to my parent, what independent information do my children give me?”

State & transition

  • State: dp[node][state] where state often means "include node" vs "exclude node".
  • Transition: dp[u] = combine(dp[v]) for all children v of u.
  • Re-rooting: When moving root from u to child v, adjust contributions in O(1) or O(log n).

P13
Pattern 13

DP on Graphs & DAGs

Guide addition

DAG DP is often just DP plus topological order. The graph may look like a shortest-path problem, but acyclicity gives you a clean dependency order.

Recognition signal

  • Finding longest/shortest paths or counting paths on a DAG.
  • Requires topological sorting before DP.
  • Can also be DP on state-graphs (shortest path with state).
Recognition promptAsk: “Can every dependency be processed before the state that consumes it?”

State & transition

  • State: dp[u] = longest/shortest path ending at u, or count of paths to u.
  • Transition: Process nodes in topo order.

P14
Pattern 14

Digit DP

Guide addition

Digit DP counts or optimizes over a huge numeric range without enumerating every number. The tight flag remembers whether the prefix is still equal to the bound.

Recognition signal

  • Count numbers in a large range [L, R] (e.g., up to 10^18) with digit constraints.
  • Constraints like: no consecutive ones, sum of digits divisible by K, etc.
Recognition promptAsk: “Can I build valid numbers one digit at a time while remembering only the constraints that affect the suffix?”

State & transition

  • State: dp[pos][tight][leading_zero][...] = count of valid suffixes from position pos.
  • Transition: Try placing digit d from 0 to limit. Recurse.
  • Tight: Whether prefix equals bound so far.

P15
Pattern 15

Probability & Expected Value DP

Guide addition

Probability DP is still recurrence design; the arithmetic is different. Expected values combine weighted successor states, while probability states sum transition probabilities.

Recognition signal

  • Compute probability of winning/reaching a state.
  • Compute expected number of steps to finish.
  • Often involves solving a system of linear equations via DP.
Recognition promptAsk: “What are the possible next states, and what probability/expectation does each contribute?”

State & transition

  • State: E[s] = expected steps from state s.
  • Transition: E[s] = 1 + sum(P(s -> t) * E[t])
  • Base: Terminal states have E[terminal] = 0.

P16
Pattern 16

Catalan & Combinatorial DP

Guide addition

Catalan-style DP appears whenever a structure is formed by choosing a split/root and combining two independent sides. The same recurrence shape appears in BSTs, parenthesizations and triangulations.

Recognition signal

  • Counting structural arrangements: valid parentheses, BST shapes, polygon triangulations, non-crossing chords.
  • Recurrence: C(n) = sum(C(i) * C(n-1-i)).
Recognition promptAsk: “If I choose the root/split k, do the left and right structures become independent?”

State & transition

  • State: dp[n] = number of valid structures of size n.
  • Transition: Try every possible split point / root.

P17
Pattern 17

Game Theory / Minimax DP

Guide addition

For two-player zero-sum games, store the advantage of the player whose turn it is. Then every move flips perspective, often turning a max choice into “my gain − opponent’s best gain”.

Recognition signal

  • Two players take turns playing optimally.
  • Usually asks: "Can first player win?" or "What is the maximum score difference?"
  • State represents whose turn it is.
Recognition promptAsk: “After I move, whose problem is the remaining state?”

State & transition

  • State: dp[i][j] = maximum net advantage for current player on subarray [i, j].
  • Transition: Player picks left or right, subtracts opponent's optimal result.

P18
Pattern 18

DP with Data Structures

Guide addition

This family appears when the DP recurrence is conceptually easy but querying all candidate predecessors is too slow. A Fenwick tree, segment tree, deque, heap or stack can make the transition fast.

Recognition signal

  • The DP transition requires querying a range (max/min/sum) over previous states.
  • Pure DP would be O(n^2); with Segment Tree / Fenwick Tree / Trie, it becomes O(n log n).
Recognition promptAsk: “What query am I repeatedly asking over previous DP states?”

State & transition

  • State: dp[i] = answer at position i.
  • Transition: dp[i] = query(0, i-1) + cost[i] where query is a range operation.

Pattern 19

SOS DP & Subset Convolution

Guide addition

SOS DP is subset-lattice DP. Instead of iterating every submask of every mask, propagate information one bit at a time so all subset/superset aggregates become available efficiently.

Recognition signal

  • Need to compute DP over all subsets of a set.
  • Classic: "For each mask, compute sum over all submasks."
  • Used in problems where properties of subsets need aggregation.
Recognition promptAsk: “Do I need an aggregate over all submasks/supermasks of this mask?”

State & transition

  • State: dp[mask] = answer for subset mask.

P20
Pattern 20

Advanced Optimization DP

Guide addition

Optimization DP is not a new state definition so much as a way to rescue an expensive transition. First derive the slow recurrence; only then exploit monotonicity, convexity or window structure.

Recognition signal

  • Standard DP is too slow (O(n^2) or O(n^3)).
  • The transition has a special form that allows optimization.
  • Techniques: Convex Hull Trick (CHT), Divide & Conquer DP, Knuth Optimization, Monotone Queue, Aliens Trick.
Recognition promptAsk: “What mathematical structure exists inside the expensive argmin/argmax?”

Techniques

  • Convex Hull Trick: Transition is dp[i] = min_j(dp[j] + m[j]*x[i] + c[j]).
  • Divide & Conquer DP: When opt[i][j] <= opt[i][j+1] (monotonicity of opt).
  • Knuth Optimization: When quadrangle inequality holds, reduces O(n^3) to O(n^2).
  • Monotone Queue: Sliding window max/min in O(1) amortized.

P21
Pattern 21

DP on Functional Graphs & Cycles

Guide addition

Functional graphs are special because every node has exactly one outgoing edge. Their components are cycles with directed trees feeding into them, so solve the trees and then resolve the cycle.

Recognition signal

  • Graph where each node has out-degree 1 (functional graph).
  • Need to find cycles and compute DP on trees feeding into cycles.
  • Common in "robot movement", "prisoner swap", "node visiting" problems.
Recognition promptAsk: “Where does repeated application of next[u] eventually cycle?”

State & transition

  • State: dp[u] = answer starting from node u.
  • Approach: Detect cycle via DFS colors. For nodes in cycle, solve simultaneously. For trees feeding into cycle, standard tree DP.

P22
Pattern 22

Broken Profile / Plug DP

Guide addition

Profile DP compresses a whole frontier of a grid into a bitmask. It is especially useful when the width is small enough that 2^width states are manageable.

Recognition signal

  • Grid problems where you fill cells row by row and need to track the profile (state of the current row's boundary).
  • Used for tiling problems, path counting with complex constraints, Hamiltonian paths on grid.
  • State is a bitmask representing the "plugs" or connections at the row boundary.
Recognition promptAsk: “What information about the unfinished boundary is sufficient to continue the construction?”

State & transition

  • State: dp[row][mask] = number of ways to fill up to row with boundary profile mask.
  • Transition: Enumerate all valid ways to fill the next row consistent with mask.
  • Complexity: O(rows 2^cols transitions). Usually cols <= 7.

Phase 4 · Perform

Interview tactical guide

A compact way to turn pattern recognition into a clear interview explanation.

The 5-Minute Pattern Recognition Protocol

When you see a DP problem in an interview, run through this checklist:

  1. Is there an optimal substructure? Can the problem be broken into smaller, similar subproblems?
  2. Are there overlapping subproblems? Would recursion without memoization recompute the same states?
  3. What defines a state? What variables completely describe a subproblem?
  4. What is the transition? How do I compute a state from smaller states?
  5. What are the base cases? What are the simplest subproblems I can solve directly?

Common Interview Mistakes

  • Not clarifying constraints: N <= 20 suggests bitmask; N <= 10^5 usually calls for O(N) or O(N log N), depending on the structure.
  • Overcomplicating state space: Start simple. Can you solve it with 1D? Only add dimensions if necessary.
  • Forgetting space optimization: In interviews, mention when the state can be reduced to a rolling array or a smaller representation.
  • Wrong iteration order: In knapsack, remember 0/1 goes backwards, while unbounded goes forwards.
  • Not handling modulo: When counting, always check whether the answer is required modulo a given value.

The “Talk-Aloud” Template

I recognize this as a [Pattern] problem because [reason].
I’ll define dp[state] as [definition].
The transition is: dp[state] = [formula] from [previous states].
Base case: [base].
Time complexity is O([time]) and space is O([space]), which can be optimized to O([opt_space]).

Final Advice

  • Don’t memorize solutions. Memorize patterns and recognition signals.
  • Write the recurrence first. Code second. If the recurrence is wrong, the code is useless.
  • Test on small examples. Trace through a 3–4 element case before declaring victory.
  • Know when NOT to use DP. Sometimes greedy, two pointers, or DFS is cleaner.

How to use this page

A repeatable study loop

1 · Recognise

Read only the problem statement and constraints. Predict the pattern before looking at a solution.

2 · Define

Write dp[state] in one sentence. If you cannot explain what a state means, do not code yet.

3 · Derive

Write the transition and base cases. Trace a tiny example by hand.

4 · Optimise

Only after the recurrence is correct, ask whether memory, iteration order, or a data structure can reduce cost.
